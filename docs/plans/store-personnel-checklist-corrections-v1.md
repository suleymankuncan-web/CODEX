Scope: the authorized checklist monthly read, Store KPI personnel table, Store Me score presentation and PNG export. Local implementation only; no deployment, live repair, snapshot rewrite or provider proof.

The Store operational report surfaces retain existing typography, neutral surfaces, primary accent, compact evidence tables and stacked mobile rows. ## Contracts and evidence

- Checklist command scores already select completions within the requested Europe/Istanbul month. The separate latest-completed query previously had no period boundary; a later completion changed an earlier month's last-visit date. Both command query variants now use the same half-open monthly bounds. Live drafts do not change closed-month status. A month with no completion displays “Checklist yapılmadı”. Stored checklist scores, templates and snapshots are untouched.
- Store KPI removes its separate returns panel and the personnel store-score-effect column. Personnel columns are gross total sales, signed attributed returns, net sales, HG%, ATV and UPT. Optional detail-only ranking `sales` values reuse the prim V2 positive-seller reader, including its accepted component/canonical-lineage verification. No gross-minus-all-returns calculation is introduced. Same-store returns reduce the seller; cross-store returns reduce the receiver store only. LP/partner stores follow the existing identity and attribution rules. Missing verified inputs remain unavailable; summary rows omit these amounts.
- Read-only investigation of the reported profile for September 2026 found 25 daily facts for each of ATV, UPT, NET_SALES, ITEM_COUNT and TICKET_COUNT, and an approved monthly HG target count of 0. Only counts and usability were retained; no identity, credentials or financial amounts are included in this note. The existing non-range benchmark reader returned unusable ATV/UPT references; the existing range reader returned usable references in the same read-only transaction. Store Me already reduced actuals using the range reader but omitted `isRange` when fetching both primary and fallback benchmarks. Passing that flag fixes the inconsistency. HG remains unavailable without an approved target; published weights and calculation rules remain unchanged. A score with no scored metrics is displayed as unavailable; a genuine scored zero remains zero.
- The previous card export already produced a PNG data URL and `.png` filename. Downloading a file is browser behavior, not evidence of an incorrect image MIME. The supported output is now a prepared `File` with `image/png`, backed by a PNG blob. Download uses a temporary object URL; supported native sharing receives that image file on a fresh user click. Image preparation follows actual dialog-preview mounting. Cancellation and closing invalidate pending generation. A web page cannot promise automatic saving into iOS Photos; the device's share sheet owns available destinations.

Contract Impact: changed — additive optional detail-only ranking `sales` field and selected-month last-visit read semantics. Existing scoring weights/rules, role/detail permissions, writes, ingestion and frozen history are intentionally unchanged.

## Risk, verification and recovery

Read/API and score-input correctness are material risks. Counterexamples include Istanbul midnight boundaries, future completions, closed-month live drafts, another store's return, unverified legacy sales, an HG target absent while ATV/UPT facts exist, no scored references and native share user-activation expiry. Targeted repository/service/unit and browser cases cover the changed boundaries. Broader local suites and live writes are outside the user's authorized verification scope. Required GitHub checks and release gates remain required before any separately authorized release.

Self-review checks period predicates, immutable-score preservation, existing role/detail masking, authoritative prim inputs, missing-data honesty, mobile width and PNG signature/MIME/name/activation. Existing routes and write paths remain unchanged; rollback is a source revert of this bounded slice, without data repair.

Source for native-share activation constraints: [WebKit User Activation API](https://webkit.org/blog/13862/the-user-activation-api/). Browser regression verifies PNG signature, filename and active user gesture; it does not establish behavior on an actual iOS device.
