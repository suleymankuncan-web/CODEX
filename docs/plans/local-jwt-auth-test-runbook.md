# Local JWT Auth Test Runbook

## Purpose
Provide the fastest way to test the real-auth-shaped frontend flow without needing a real external identity provider yet.

This path is meant for:
- local development
- shell routing checks
- callback flow checks
- `/api/auth/session` verification checks

## What This Path Uses
- backend `AUTH_MODE=jwt`
- HS256 verification with `JWT_SECRET`
- a local token generated by the backend script
- frontend callback route:
  - `/auth/callback`

## Generate Token
In backend folder:

```powershell
npm.cmd run auth:token
```

Default output shape:
- one HS256 JWT
- one ready-to-open callback URL
- default role:
  - `STORE_MANAGER`
- default state:
  - `/store`

## Open Callback URL
Take the printed callback URL and open it in the browser.

This manual `access_token` callback path is development-only. Production frontend builds reject `access_token` / `token` callback URLs and keep Authorization Code + PKCE as the only real provider path.

Expected example shape:

```text
http://localhost:5173/auth/callback#access_token=...&state=/store
```

## Expected Result
1. frontend callback stores the token
2. frontend calls `GET /api/auth/session`
3. backend verifies token with `JWT_SECRET`
4. frontend resolves roles and scope
5. app lands in `/store`

## Admin-Oriented Example
If you want admin routing instead:

```powershell
npm.cmd run auth:token -- --roles SUPER_ADMIN,REPORT_VIEWER --state /admin/reports
```

## Store-Oriented Example With Explicit Scope
```powershell
npm.cmd run auth:token -- --sub store-manager-1 --roles STORE_MANAGER --company-ids 00000000-0000-0000-0000-000000000001 --region-ids 00000000-0000-0000-0000-000000000010 --store-ids 00000000-0000-0000-0000-000000000100 --state /store/tasks
```

## What This Path Proves
- real callback route works
- bearer session persistence works
- backend JWT verification works
- shell routing works
- store/admin split works without mock headers

## What This Path Does Not Prove
- real IdP redirect
- JWKS verification
- provider logout
- provider callback quirks
- authorization code + PKCE exchange
